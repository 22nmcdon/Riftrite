# CLAUDE.md

## Project

A PvE roguelite auto-battler (working title **Riftrite**, a placeholder). The player leads three heroes into the rift, one day at a time: they place the heroes in an arena before each fight, then watch it play out. Each hero is vowed to a path and transforms into it by doing what the path asks in fights.

**The game is being rebuilt from scratch.** The design is `docs/design.md`, built from the rebuild plans in `docs/plans/`:

## Tech stack

- Engine: Godot 4.7, GDScript (static typing everywhere: `var hp: int`, typed function signatures). `project.godot` makes untyped declarations a compile error, and the test run fails if any script in `src/`, `tests/`, or `tools/` doesn't compile.
- Tests: GUT (Godot Unit Test)
- Game data: JSON files in `data/`, loaded at startup and validated
- **Pinned versions:** Godot `4.7.2-stable`, GUT `9.7.1` (vendored in `addons/gut/`). Upgrade either one only on purpose, in its own change, and rerun the determinism tests afterward. The Godot version also appears in `.claude/hooks/session-start.sh`, `.github/workflows/*.yml`, and `tests/test_project_setup.gd` (which checks the others); keep them all in sync.

## Commands

- Run the game: `godot --path .` (main scene `src/ui/main.tscn`: the title, then Practice)
- Screenshots of each screen (needs a display): `xvfb-run godot --path . -s tools/ui_screenshots.gd -- --out=/tmp/shots` (the title, the encounter list, placement and choosing a tactic, fights mid-way with a popup and an area warning, the result, Rift Collapse with the log open, the team row and a fight of Garrow, Tamsin, and Aldous, the draft, and a run through all three acts)
- Placeholder figures and the title backdrop: `python3 tools/art/hero_kit.py` (and `enemy_kit.py`, `backdrops.py`), then `godot --headless --path . -s tools/art/figure_bounds.gd` to refresh `art/figures/bounds.json` (a test checks it)
- Item glyphs (after adding icons to `art/ui/items/`): `python3 tools/art/item_glyphs.py` splits each icon's glyph from its frame into `art/ui/items/glyphs/` (and writes the graft frame), then `godot --headless --import`
- Run all tests: `godot --headless -s addons/gut/gut_cmdln.gd -gexit` (settings in `.gutconfig.json`)
- Run one test file: add `-gselect=test_project_setup.gd`
- Fresh checkout: run `godot --headless --import` once first, so class names are registered. The session-start hook does this in cloud sessions.
- Validate game data: `godot --headless --path . -s tools/validate_data.gd` (the sim's files and the run's; also covered by the test run)
- Time the arena sim against its budget (a 60s fight of 3 against 6 in under 100 ms): `godot --headless --path . -s tools/bench_sim.gd`. It runs a steady fight, a crowded worst case, a summon swarm, and a fight where every hit starts a chain to the limit, and prints each fight's log fingerprint, so a speed-up can be checked to change nothing.
- Fight every encounter from placed parties and check that placement matters: `godot --headless --path . -s tools/sim_runner.gd -- [--encounter=id] [--seeds=50] [--sweep=40] [--no-boards]` (formations in `tools/sim_formations.json`, by role: tank, far, mid; exits 1 if an encounter fails the gate). Seeds only change crits, so `--seeds=5` is enough while tuning. ## Rules the code must never break

1. **The combat sim is deterministic.** Same seed + same inputs = same fight, every time. Use only the sim's seeded RNG (never `randi()`, `randf()`, or unseeded RandomNumberGenerator). Use a fixed timestep, not frame delta. Never iterate a Dictionary where order affects the outcome.
   - **Integer math only in `src/sim/`.** No `float`: HP, damage, shields, stats, and positions are `int`; percentages are basis points (`10000` = 100%); time is ticks at a fixed **20 ticks per second**; on the arena's plane, **1 hex = 1000 units**. Data files give durations in milliseconds, and the loader converts them to ticks. Round with explicit integer division, in one shared helper.
2. **The sim is separate from presentation.** `src/sim/` never references nodes, scenes, animations, or UI. The UI plays back events the sim emits.
3. **Content is data, not code.** Heroes, enemies, encounters, paths, upgrades, relics, and duo bonds are JSON entries using existing effect, trigger, and part types. Only add a new effect type in code when no combination of existing ones can express it, and say so when you do.
4. **Every combat effect writes to the combat log** with its source (unit and ability, relic, duo bond, status, or Rift Collapse). Every move, push, shot, and area is logged too. If a player can't trace why something happened, it's a bug.
5. **Meta progression never adds stats.** Unlocks add variety (heroes, camp options, places, relics), cosmetics, and codex entries only.

## How the arena sim works

The details and every decision are in `docs/plans/rebuild-phase1-arena-sim.md`; each module's header comment has its rules. In short:

- **Setup** (`FightSetup`, `UnitSetup`): units on hexes of an 8 × 7 flat-top grid (`HexGrid`, odd columns shifted), rocks, a seed, an act, and the kits summons may use. `validate` refuses what can't be fought. Kits (`UnitDef`) are data: stats, a targeting rule, traits (`engage`, `flying`, `hop_away`), a basic attack, an optional signature and mana bar, passives (`PartDef`), and phases (`PhaseDef`).
- **The plane:** once the fight starts, units move freely (1 hex = 1000, units are circles of radius 100, so 0.2 hex wide, rocks 500) and never overlap. Melee (range 1) reaches half a hex (`melee_reach`), center to center; range 2 and up reach that many hexes. A unit with no way to its target keeps it and waits for an opening, unless rocks wall the target off; then it picks again. A stealthed enemy (the `stealth` status) can't be picked, and a unit targeting one picks again. (Sizes, reach, that rule, and Stealth came with playtest gate 1.) Walking is straight when clear, otherwise along an A* route on hidden 125-unit cells (`NavGrid`). Crumbled ground is walkable (phase 5c): a step onto it costs 3x in the route, a unit with nothing to do steps off it (`Movement.wait`), and spots a unit picks to land on (leaps, hops, summons) stay on safe ground (`CombatSim.fits`; walking uses `fits_ground`). Every leg is logged, so the board replays from the log.
- **The tick** (`CombatSim.step`, 20 a second): auras whose window changes; Rift Collapse (`Collapse`); statuses (`Statuses`); shots landing (`Shots`); warned areas landing (`Areas`); each standing unit's update in the fight's order (heroes, enemies, then summons as they join): mana, signature (`Signatures`), Stun, attack cooldown, target (`Targeting`, sticky), then attack or walk (`Movement`, `Engage`, `Displacement`); events from this tick's log (`Events`, `Passives`), then timed passives, and phases (`Phases`); deaths (Undying, would_fall, on_fall); the end (180s is a tie, a guild win).
- **Effects** (`EffectRunner`, `EffectDef`): damage, heal, shield, statuses, cleanse, mana drain, knockback, pull, leap, charge, warned areas (circle, ring, line, cone; hit by center), summons (`Summons`), and start_collapse. From 2 hexes or more, an attack is a shot that flies about a tick per hex, with its numbers fixed as it leaves.
- **The damage rule** (`DamageRule`, phase 5c step 1a): damage, heals, Shields, and damage over time are a base times one factor per bonus kind: **power** (the unit's output auras, a kit mod's `amount_bp` as the effect's `power_bp`, a tactic's payoff), **crit**, **vulnerability** (Marked; healing taken on heals), and **relic**. Bonuses of one kind add, the kinds multiply, each kind is floored at −90%, and the number is rounded once where it lands (`EffectRunner.land`, `deal_hit`, `heal`; shots, areas, and snares carry each effect's power). Auras of one stat add their changes too (x1.1 and x1.1 make x1.2).
- **Passives** (`Passives`, `PartDef`): auras (a window, or `"while": "taunting"`), status swaps, and effects on the unit's events (read from the log), on `on_ally_below_hp` and `on_interval` (after the events each tick), or `on_fall` (in the deaths step). What they do is marked from_event and can set off more events: a **chain** (phase 5c step 3). Each log entry carries its depth (`LogEntry.chain`), `Events.dispatch` keeps reading while the log grows so a chain resolves in its tick, and an entry at `chain_limit` (`tuning.json`, 8) sets off nothing; a kill carries its hit's depth.
- **Keywords and conditions** (phase 5c step 3, `rebuild-phase5c-combos.md` section 8): `Keywords` names a unit's state for cards: Marked, Rooted, Burning, Stealthed (a status's `"keyword"`) and Shielded (Shield above 0). `UnitCondition` is "a unit that is ..." (keywords, statuses, below an HP share, flying, archetypes): an event effect's `"vs"` (the unit the event names), a `damage_bp` aura's `"vs"` (power against targets that meet it, added in `deal_hit`; every "+X% damage to some enemies" is power, Decision 12), and an aura's `"while": "state"` (its holder).
- **Triggers** (phase 5c step 3): beside the built events, `on_holder_hit` (a hit on an enemy, not damage over time), `on_shield_broken` (a hit or damage over time takes the last of the unit's Shield; DAMAGE and STATUS_DAMAGE entries carry `broke_shield`), and `on_ally_ability` (an ally's signature fires). `on_status` takes `keywords`; event effects take `once`; `on_kill` names the fallen (for `vs`), credited to the last to hit it (Decision 13). Team-wide cards are passives on every hero (a relic's `mod`).
- **Tactics** (`Tactics`, `TacticDef`, phase 3b; 14 with three ranks since phase 5c step 6c, `rebuild-phase5c-combos.md` section 14.14): a hero's one tactic changes how it behaves, never what it can do, and a unit without one never reaches the code, so tactic-free fights are unchanged. Any hero takes any tactic it can follow (`Tactics.can_follow`); stat payoffs are auras on its kit `"while": "tactic"` (`kit_with_payoff`, `applies`); `TacticDef.at_rank` gives ranks II and III. The built three:
  - Casters first: `Targeting.update` picks the nearest enemy of the tactic's archetypes first; its own attack and signature deal 20% more to them (in `EffectRunner.deal_hit`).
  - Hold your ground: no walking until an enemy is within 2 hexes, then let go for good; it attacks 20% faster while it holds.
  - Wait to heal: a full bar waits until the ally its signature picked is below 60%; the heal it lets go is 15% stronger.
  Each logs TACTIC lines sourced to the unit and the tactic. A payoff (round 2: small, and only while the behavior applies) shows on the hit or heal as the log entry's `bonus` ("+20% from Casters first"). - **The void and islands** (`Islands`, phase 8 part 3, `rebuild-phase8-act3.md` section 3 and its "Built in 8c-5b"; a fight without void never makes one): an encounter's `"void"` hexes (`FightSetup.void_hexes`; never on a rock or water, no unit placed on it, every enemy on an island the heroes' rows reach). A point is over the void when its nav cell's center is (`CombatSim.on_void`). Walkers can't cross it (`NavGrid.void_cells`, `fits_ground`, `Islands.crosses` in planning); fliers ignore it; `fits` refuses it, so landing spots stay off it; a charge and a hop stop short (`Islands.solid_until`). A unit that doesn't fly whose push ends over the void falls (`Islands.check_fall`): the log kind FELL, `UnitState.fell`, and a death in the deaths step that nothing catches or follows (no Undying, would-fall save, on_fall, or rise), a kill for whoever pushed. The board draws the void as sky. 8c-5c-1: an encounter's `"bridges"` (`FightSetup.bridges`) and the effect `sever` (the next bridge in turn is warned, breaks into void with falls, and reforms; `Islands.tick`; the log kind VOID; a warned bridge tinted red), a pull's `"to": "beside"` (a hook, `Displacement.hook`), a knockback's `"toward": "edge"` and `"distance_bp"` (`Displacement.shove_to_edge`), and any effect's `"when_attackers"` (`EffectRunner.attackers_on`; `"when_attackers_kits"` counts only those kits, 8c-6c). 8c-5c-2: the aura stat `miss_bp` (basic attack hits miss on the seeded RNG; DODGED noted "missed"), a zone's `"follows": "nearest"`, an event effect's `"delay_ms"` (`Passives.run_delayed`), a leap's `"to": "start"` (`UnitState.start_pos`), and the extra signature trigger `"every"`. 8c-5c-3: the passive kind `copy` (`Copies`, `CombatSim.copiers`: a hero's copyable signature becomes the copier's own, on its bar, sides turned; `replace`, `twice_pct`, `share`; the log kind COPIED). 8c-6a: Act 3's ten enemies (the Cliffmite, Cragram, Gulf Angler, Spire Chanter, Mirrorwight, Unbinder, Great and Herd Cragram, the Mirror Queen, the Heart of the Rift), an aura's `"only"` (receivers that meet a UnitCondition), `ally_standing` without a kit, the trigger `on_breaks_shield`, the targeting rule `loneliest`, a kit signature's `"also_fires"`, a count cleanse's `"statuses"`, and a bridge's hexes being no island's (`same_island` never holds on a bridge).
- **The bond relics' pieces** (phase 5c step 5d, section 13.3): an aura `"while": "behind_wall"` (`Walls.behind`), and the triggers `on_knockback` (PUSH lines noted "knocked back") and `on_guard` (GUARD lines), with an event effect's `cooldown_per_unit_ms`.

## How the content works

Phase 2's details are in `docs/plans/rebuild-phase2-heroes-enemies.md` (sections 2–7 and their "Built in step N" notes). In short:

- **Files** (`ContentDb` loads and cross-checks them): `heroes.json` (`HeroDef`: name, title, role, and a kit), `enemies.json` (`EnemyDef`: archetype, threat line, and a kit, phases included; the kit carries the archetype too), `encounters.json` (`EncounterDef`: enemies on hexes, optional rocks, act, days, and `scale_bp`), `tactics.json` (`TacticDef`, phase 3b: a kind, its numbers, and the heroes who can take it; a hero takes one through `Encounters.setup`'s tactics map, as `UnitSetup.tactic`), and `paths.json` (`PathDef`, phase 4: a hero's path, with its taste, cost, transformation, and deed; up to three per hero, added wave by wave). A hero's or enemy's kit is a `UnitDef` without its own id or name; heroes and enemies share one space of ids. Heroes act in `heroes.json`'s order.
- **A fight from content:** `Encounters.setup(content, encounter_id, formation, seed, errors)`, where a formation is hero id -> hex. It adds every enemy a unit may summon as a summon kit, and scales enemies' HP and ATK by `scale_bp`.
- **Ability text:** every basic attack, signature, and passive of a hero or enemy has a `"text"`: the player's sentence for it (the sim never reads it). It says what the ability is for and **names every reach** ("within 4 hexes"), since the board never draws one; `test_unit_info.gd` checks both. Keep numbers out of it: the UI adds a numbers line generated from the kit.
- **Numbers:** hero stats are the design's. Enemy HP, ATK, and a few kit numbers come from step 7's first tuning pass. Change numbers with the sim runner, not by hand-feel.
- **The sim runner** (`tools/sim_runner.gd`, its work in `tools/sim_report.gd`) fights each encounter from the named formations in `tools/sim_formations.json` and from drawn ones. **The gate:** the best formation wins at least 30 points more often than the worst. From Act 2 on it fights a transformed team (the Gallery's paths) against enemies scaled down to stand for a run's team (`SimReport.gate_scale_bp`: from x0.67 for fights from day 1, x0.55 for later ones, stepped until the formations split); `--act=N` runs one act. Seeds only change crits, so formations mostly win all or nothing; the report also counts how many formations win, and tuning aims for about a third to two thirds.
- **Tests:** `test_hero_kits.gd` and `test_enemy_kits.gd` check each kit's text in small fights; `test_encounters.gd` checks every encounter builds and plays out; `test_arena_log.gd` replays and audits a fight of the three heroes against one of each enemy; `tests/tools/test_sim_runner.gd` runs the runner small. Content changes that should move numbers change these tests on purpose.

## How the run works

The details and every decision are in `docs/plans/rebuild-phase5-run.md` (its "Built in step N" notes and Decisions). In short:

- **Content** (`RunContent`, beside `ContentDb`, which it cross-checks): `act1.json` (`ActDef`: the days, pay by tier, starting shards, losses to end, slots, the pick's shards and wild cards, shop prices and sizes), `upgrades.json` (`UpgradeDef`: hero, taste, and path cards, phase 5c step 7), `items.json` (`ItemDef`: charms, tactics that name `tactics.json`'s, sigils, and gambits, each with three ranks), `camps.json` (`CampsDef`: options, places, Fortify's and Rift Tear's mods), `relics.json` (`RelicDef`), `bonds.json` (`BondDef`), `events.json` (`EventDef`, phase 5c step 8c). Paths' deeds carry a `threshold`; encounters a `tier` (`easier`, `harder`, `elite`, `boss`, `hunt`).
- **Kit mods** (`KitMod`, in `src/sim/defs/`): the one shape for upgrades, items, relics, bonds, camp's modifiers, and enemy upgrades, written against slots (stats, `basic_attack`, `signature`, `abilities`, `passive:<id>`, added passives, mana, extra signature triggers, Echo). `Encounters.setup` takes `extras` (hero id -> `HeroExtras`: mods and wounds) and applies the mods after the path's patch; wounds lower max HP (`UnitSetup.max_hp_bp`). A fight is still a pure function of its setup; a kit with no mods is unchanged.
- **The team** (phase 8 part 4, `rebuild-phase8-heroes.md`; `HeroTeam`, `src/run/hero_team.gd`): a run's three heroes are drafted on the vow screen; `RunFlow.start` takes the team from the vows' keys (three different heroes whose paths are all built: `HeroTeam.ready`, `problem`) and `state.heroes` is the team in heroes.json's order; `fight_setup` refuses a hero off the team. Roles place any team (`HeroTeam.roles`: tank by HP x (100 + DEF), far by range, mid; `place`, `GUARDED`): the sim runner's formations, the bots' formation, and Practice's first formation are by role. Practice's team row fields any three (`PracticeSession.team`, `set_team`; an unready hero at base); `HeroBar` and `HeroPanel` follow the session's team. Reports cycle teams with vows by seed (`run_report.gd`'s `vow_combinations`), and `--team=a,b,c` fixes one.
- **The state and the rules:** `RunState` is everything a run is (saved as versioned JSON by `RunSave`); `RunFlow` is the only thing that changes it, one action at a time, each returning "" or why not. Offers are pure functions of the seed and the state (`Offers`, `ActDraw`, on `RunRandom` streams by what, act, day, attempt, and visit), so a save holds only the state. A fight is `RunFlow.fight_setup` then `CombatSim.run` (the arena plays the same setup and records `CombatSim.result_of` its sim).
- **A day** (phase 5c step 8a, `rebuild-phase5c-combos.md` section 16; `RunState.Phase`: ROUTE, LOADOUT, AFTER, SHOP, NODES, NODE, CHOICE, ENDED): the route (today's two fights, drawn at the act's start; day 1 starts here), the loadout, the fight, after it (transformations, the pick, a relic choice), the shop (the Pedlar, after every fight; on the boss's day, after the boss relic choice, the boss shop, and leaving it leads to endless's choice, or ends the run in an act without endless: Decision 48, phase 8), then a node (`Offers.nodes`: Camp always, and two drawn from Event, Rift Tear, and the Magpie, he from day 3 and at most twice an act, a repeat drawn as an Event; `CampsDef.nodes`): Camp (a place's options: one), Rift Tear (tomorrow's fight, at a depth: `choose_depth`; step 8b), the Magpie's stall, or an Event (step 8c); then the next day. The boss's day is the fight, its relic choice, and the boss shop. A loss replays the day from the route, and what a node set up for that fight (Fortify, Dig In, a Rift Tear) holds until it's won (Decision 42); the act's second loss ends the run. A won fight heals one wound on each hero before the fallen take theirs (playtest gate 3). A Hunt is fought in a Camp node and never counts as a loss. `RunState.taken_nodes` keeps each day's node for the act map.
- **Events** (phase 5c step 8c, section 16.7; `data/events.json`, `EventDef`, `RunContent.events`): an Event node is a scene ("event:<scene id>") or, 1 time in 4, a Bloodied Oath ("oath"). A scene's choices carry results, named run actions (`EventDef.RESULTS`, done by `RunFlow.choose_event(index, target)`; `event_problem` says why one can't be made, and the screen greys it); leaving without a choice is walking away. Effects for the next day fight (`Hero.next_fight`) go last among its mods and are spent once it's won; The Old Well's cut lasts the act (`Hero.weakened`); a sealed Bleeding Tear wins the next day's fight unfought (`RunState.sealed`). An oath (`take_oath`, `Hero.oath`, `oath_fights`) lasts its hero's next 2 day fights: deeds doubled, and its burden (a kit mod, the front row, no tactic, or 2 wounds a fall). The kit mod `drops_signature` removes the signature and mana bar; a tactic the kit then can't follow is set aside.
- **Rift Tear and the Shrine** (phase 5c step 8b, section 16.5–16.6; `camps.json` `rift_depths` and `rift_modifiers`, `CampsDef.Depth` and `Modifier`): Shallow, Deep, and Abyssal: every depth's enemies start with a Shield of 10% of max HP (`rift_tear_mod`), Deep adds the day's first rift modifier and Abyssal both (`Offers.rift_modifiers`), and a win offers a relic of each of the depth's tiers (`Offers.relics_of_tiers`). A modifier is a kit mod on enemies and summon kits, one on the heroes (Blight), Early Collapse (`FightSetup.collapse_start_ticks`), or Reinforcements (`FightSetup.rift_effects`, run by `CombatSim._rift_due`, sourced to the rift: `EffectSource.rift_effect`). The Shrine takes an offering (`shrine_offer`: shards or a wound for a rare, a relic for one a tier higher; `RunState.shrine`), spent only if the relic is taken.
- **Endless** (phase 8 part 1, `rebuild-phase8-endless.md`; `endless.md`): `act1.json`'s `endless` block (`ActDef.Endless`). After the act's boss shop the run waits at `Phase.CHOICE`: `RunFlow.end_run()` (won) or `go_deeper()`. A **floor is a day after the act's last** (day 8 is floor 1; `RunContent.day_kind` says what any day is, and nothing reads the act's days directly; `floor_of`, `floor_pool`), so the day's loop, the nodes, and the save carry on. A floor offers one fight (Decision 2), drawn two floors ahead (`Offers.endless_floor`) from Act 1's fights from day 4 on (Decision 1): an elite every 5th floor, Old Mother Ash every 10th. Its enemies' HP and ATK grow ×1.15 a floor, compounded (`Endless.compound`); a rift modifier is gathered every 3rd floor for good (`RunState.endless_mods`, `Offers.endless_modifier`, no repeats); Rift Collapse starts 1s sooner a floor (never before 10s) and crumbled ground hurts ×1.15 a floor (`FightSetup.crumble_bp`, the one sim piece). A floor has no shops and no upgrades (Decision 6, 2026-10-03): no Pedlar, and the pick (and Camp's Train) offers only apex cards (`Offers._offered`); the Magpie stays among the nodes. A boss floor offers boss relics, then legendaries once all are held; pay stays flat (Decision 4). The first loss ends the run, still won; the deepest floor goes in `RunRecords` (`user://records.json`). Save version 5 (version 4 still loads). Small calls flagged in the plan: the Magpie's visits count afresh after going deeper and each endless boss floor, no Hunts on floors, Map the Rift swaps within the floor's pool. The bots answer the choice with `Bot.go_deeper` (the `deeper` flag, set by `--endless`). The screens: the choice stage, "Floor N · Endless", the floor's card with its numbers, the end with the record, and `UiStyle.short_number` for big numbers. Tests: `tests/run/test_endless.gd`.
- **Apexes in the run** (phase 8 part 2): leaving Act 1's boss shop opens the apex vow (`RunState.apex_open`; phase 8 part 3, it was on going deeper); a transformed hero's path's apexes' deeds count from then (or from a later transformation), `RunFlow.vow_apex` vows (free to switch until earned; `apex_waiting` lists who can), and the vowed apex's deed filling earns it (`Hero.apex_earned`, `state.just_apexed`); `RunContent.hero_kit` is then the apex's. Save version 6. The bots answer with `Bot.apex`; the day shows "The apex vow is open", and the hero panel the apex cards.
- **Acts** (phase 8 part 3, `rebuild-phase8-acts.md`; 8c-1 built the frame): `RunContent.acts` (act1.json, then act2.json and act3.json where they exist), `act_of(state)`, `next_act(state)`, and `RunFlow.act`; nothing reads one act directly. Leaving an act's boss shop (`_end_of_act`) opens the apex vow, then waits at the choice if the run may go deeper (`can_go_deeper`: an act with endless, its testing one only in a testing run), else starts the next act (`_next_act`: day 1, its fights drawn, each day's node, Scout, the Magpie's visits, and The Old Well's cut afresh; losses and everything else carry, so any two losses end the run), else ends the run won. `act1.json`'s endless is the testing option (`"testing": true`; `RunState.testing`, the start screen's checkbox, the bots' `--endless`). `ActDef.fights_act` lets a stand-in act draw another's fights (`tests/run/test_acts.gd`'s stand-ins). Each fight records its act; records are kept by the act their endless follows, with the furthest act any run reached (`RunRecords.furthest`). The run report adds **By act** when there's more than one (8c-2), with the runs that reached each act's boss and how many held an apex, and **Apex vows** (each apex's vows, earns, act and day, and its deed a fight: what sizes the apex deeds). Save version 7. The game has Act 1, Act 2, the Glassmere (8c-4b: `act2.json`, its fights in `encounters.json` with `"act": 2`), and Act 3, the Shattered Crown (8c-6b: `act3.json`, specialized from day 1 at 75%, 1–2 upgrades on elites, the rift learns, and the real endless after it; its fights over the void with `"act": 3`; tuned in 8c-6c: the good bot clears it in 8 of the 13 runs that reach it, 11% of all runs).
- **Enemy specializations** (phase 8 part 3, `rebuild-phase8-act2.md` 8c-3a; `enemy-growth.md`): an enemy's `"specializations"` (up to two `SpecializationDef`s: a word, a sentence, a kit mod; `ContentDb.specializations`). From an act's `specialized_from_day` (Act 1: never), each day start draws today's fights' (`Offers.specializations`, `RunState.today_specs`): half of a fight's enemies, rounded down, among those that have any, each one of its own; fresh on each attempt, none for Hunts or endless floors. `RunFlow.chosen_specs` passes the chosen fight's to `Encounters.setup`'s `enemy_specs`; a specialized kit carries the word in its name and `UnitDef.specialization`. - **Enemy upgrades** (phase 8 part 3, `rebuild-phase8-act3.md` 8c-5a; `enemy-growth.md` section 3): `data/enemy_upgrades.json` (`EnemyUpgradeDef`: a word, a sentence, a kit mod; `ContentDb.enemy_upgrades`), any enemy can carry any. The economy is `economy.md`'s (start 10; wins 10/13/15/25). Step 5b (section 11) adds what relics share: effects at a fight's start (`RelicDef.at_start`, passed in `FightSetup.relic_effects`), Salt Circle (`FightSetup.salt_circles`), and Reliquary (a common counts twice: `RunContent.counts_twice`, its mod `times(2)` where a step could scale it, its run rules and start effects doubled). Step 5c-1 (section 12.1) adds the engines: a relic's `"rules"` (`SideRules`, merged by `RunContent.hero_rules` into `FightSetup.hero_rules`; 5c-1's one is `marks_stack`) and `"mod_for": "ranged"`. Step 5c-2 (section 12.2) adds the rest of the heroes' rules. Step 5d (section 13) makes duo bonds keys: a bond has no boost, and once on, its free bond relic (tier `bond`) is 20% of the shops' relic draws (`Offers._bond_relic`, `RunContent.bond_relics`). All 89 relics are built. Wounds go to heroes down at the fight's end (`FightResult.down_at_end`, Decision 23).
- **The loadout** (phase 5c step 6, `rebuild-phase5c-combos.md` section 14; `loadout/`): a run owns one of each item at a rank (`RunState.item_ranks`, `item_counts`); a bought copy is a rank up. Each kind ranks up by its own count while equipped (`ActDef.item_ranks`): charms won fights, gambits fights, tactics the time their hero stands (`ms_standing`), sigils their signature's `casts` (the last two tallied in the fight under `item:<id>`). Prices are by kind (`ActDef.item_prices`); the Pedlar buys items back for half (`RunFlow.sell`). Shops never filter by what the team can use, nothing warns that an item does nothing, and an item at rank III is never offered. One tactic and one gambit per hero.
- **The upgrade pools** (phase 5c step 7, `rebuild-phase5c-combos.md` section 15; `upgrade-pools.md`): three layers (`UpgradeDef.layer`): a hero's own cards, always offered; its vowed path's taste cards, until it transforms (each carries on after with its `transformed_mod`, Decision 35); and its path's cards once transformed (`RunContent.upgrades_for`). The pick never offers a card that changes nothing on the hero's kit now (`changes_something`, Decision 37). A stacking card (`"stacks"`) locks in a share of the hero's stat at the time as a flat amount (`stack_amount`, `RunState.Hero.locked`; attack speed's share is of 100 + ATSP) and can be taken again. The pick's shape is unchanged (one card per hero, the wild card, every card equally likely; Decision 38).
- **The Magpie** (phase 5c step 6e; `magpie.md`): a node (step 8a), two charms at rank II, a relic at 25% off, and he buys relics (`RunFlow.sell_relic`, `ActDef.relic_sell`) and swaps one a visit for one of its tier (`swap_relic`, `Offers.magpie_swap`); he doesn't buy items.
- **The bots and the report:** `tools/run_bot.gd` plays whole runs by simple rules (the tests use it); phase 6's bots (below) play for the report; `tools/run_report.gd` measures many.
- **Tests:** `tests/run/` (the flow, growth, the economy, camp, relics and bonds), `tests/sim/test_kit_mods.gd`, `test_sigil_pieces.gd`, and `test_elite_pieces.gd` (the sim pieces), `tests/tools/test_run_report.gd`, and `tests/ui/test_run_screens.gd`.

## How the bots work

- **The frame:** a bot (`bot.gd`) answers each decision (the team it drafts, `Bot.team`: the old three, the random bot's any, the good bot's by practice fights; the route, the loadout, the formation and markers, the pick, a relic, the shop, the node, camp, a depth, an event, an oath, the Shrine, a swap, a rock); `run_player.gd` plays the run with its answers through `RunFlow`. The base answers as the simple bot does.
- **The random bot** (`random_bot.gd`): random legal answers from its own seeded `SimRng`. **The good bot** (`good_bot.gd`): it places by reading the fight (`placement.gd`: 26 features of a formation, each weighted by what the fight holds, from `placement_weights.json`, fitted by `placement_data.gd` and `fit_placement.py` on practice fights; a fight with water is scored by the file's `water_weights`, fitted on Act 2's fights alone with `--water`, so Act 1's placement doesn't move; a fight over the void by its `void_weights`, fitted on Act 3's alone, with two more features, `void_near` and `pushed_off`, both 0 without void), never by fighting it, and judges choices by practice fights (`practice.gd`: a copy of the run, fought on practice seeds against the act's fights more than a day away, then fights already behind; never the next fight, Decision 5), plus shards at a worth that falls as the act runs out. **The expert** (`expert_bot.gd`): the good bot trying its 6 best formations in the real fight: the ceiling.
- **Tests:** `tests/tools/test_bots.gd` (each bot plays and repeats; the quick score is the features' score; placement is legal and fights nothing; the expert never does worse; practice never holds the next fight and changes nothing real; the reports).

## How the UI works

Phase 3's details are in `docs/plans/rebuild-phase3-fight-sandbox.md` (sections 1-9, their "Built in step N" notes, and its Decisions). In short:

- **Screens:** `Main` shows one `UiScreen` at a time and moves between them on their signals: the title, then Practice's `EncounterListScreen`, then `ArenaScreen`, which holds placement, the fight, and the result. `PracticeSession` keeps the remembered formation, the speed, the log's state, and the seed while the game is open; nothing is saved to disk.
- **Every card's amounts** (`ModInfo`, phase 5c step 2): an item's, upgrade's, relic's, or duo bond's sentence says what it's for, and a numbers line generated from its kit mod (or tactic, or a relic's run rules) says how much ("+15% DEF · Signature: +1 hex area"), on its card, in the hero panel, and in tooltips; aura amounts read as signed percents ("+50% DEF").
- **The item language** (phase 5b): `ItemIcon` draws a kind's frame (`art/ui/items/frames/`) with a glyph (`art/ui/items/glyphs/`) in the kind's color; items and relics name their glyph (`"icon"`), camp's options and places their icon file. They show on the hero bar's chips, the item, relic, and upgrade cards, the top bar's relics, and the hero panel. `test_art.gd` checks everything the data and the UI name loads.
- **The run's screens** (phase 5): the title's New run and Continue, `RunStartScreen` (the vows), `RunDayScreen` (the top bar, what's waiting, then the day's step: the route as the act map (`ActMap`: an island a day, today's fights clickable, the selected one's card beside it, and each past day's node), the loadout, after the fight, the shop, the nodes (a card each), a node (camp's options, the Magpie's stall, a Rift Tear), or the end; a shop is a `ShopStage`, the keeper in his scene behind the wares), and `ArenaScreen` in run mode (the run's top bar, Dig In's rock, Continue). `RunSession` is Practice's session over a `RunFlow`, so the arena, `HeroBar`, and `HeroPanel` show the run's heroes (wounds, deed progress, items, Switch vow, upgrades, bonds); it saves after every action.
- **The UI never changes a fight** (rule 2). `FightPlayer` owns the `CombatSim` and is the only thing that steps it:
  - `advance(seconds)` steps whole ticks at 0.5x, 1x, or 2x; tests pass fake time.
  - A seek or restart builds a fresh sim and runs it to that tick.
  - Units are drawn between their last two ticks (`drawn_position`, `drawn_time`).
  `test_every_encounter_plays.gd` checks that each encounter played on the screen is exactly the fight `CombatSim.run` gives.
- **The board** (`ArenaView`): the plane mapped to pixels with the heroes at the bottom and the enemies at the top (phase 5b: the plane's columns run across the screen and its rows up it), centered at the screen's full height, over the rift's sky; the board stands on the floating island (`art/ui/arena/`: the frame, tiled ground, pale hex lines, Rift Collapse's tiles), and rocks are ruins (`RockProp`, picked by the hex); one `UnitToken` per unit, drawn as its figure (`FigureArt`: `art/figures/`, a hero's base form for now) standing on its point on a gold or red ring, nearer units (and ruins) in front, with its bars over its head and status tags read from `UnitState` each frame; `FightFx` above them for what the log says happened (shots, swipes, numbers, areas, slides, ghosts, rings), plus the ground layer (areas, Rift Collapse, target and Engage lines). Effects run on the fight's clock; a batch of more than 60 entries (a skip) clears them instead. The view resolves clicks itself (`token_at`).
- **Placement:** heroes are dragged onto hexes; what's legal comes only from the sim (`Encounters.setup` and `FightSetup.validate`, through `PracticeSession.errors`). The board never draws an enemy's reach (Decision 5).
- **Beside the board:**
  - on the right, the side column: the encounter's name and hint, `EnemyPanel` on hover, the controls and the `FightChart` during the fight, and the result when it ends (outcome, seed, heroes, chart, Rematch, Watch again);
  - on the left, an empty gutter as wide as the side column (it keeps the board centered), where the combat log (`LogPanel`) pops up with its button or L;
  - `HeroPopup` beside a hero clicked while the fight is paused or over. It and `EnemyPanel` are built by `UnitInfo` (the data's sentence plus a generated numbers line). Its Tactic row (phase 3b; the sentence and a numbers line from `UnitInfo.tactic_numbers`) names the tactic taken.
  - the look (`UiStyle`) follows the playtester's mock (`docs/mockups/hero-panel-layout.pdf`): its navy, teal, gold, and cream palette, Cinzel and Alegreya (OFL, in `art/fonts`; phase 5b), flat rounded boxes. The arena screen has the mock's top bar and **hero bar** (`HeroBar`: a card per hero with portrait, path, HP, vowed deed, and Charm/Tactic/Sigil chips); clicking a card opens the hero's panel (in a fight it pauses, and the panel is read-only). Clicking a hero on the board opens nothing while placing.
  - the **hero panel** (`HeroPanel`, phase 4, laid out after the mock's page 1) over the screen above the hero bar: the figure and stats, back and forward, and Path (the track, the vowed card, the other paths, Vow/Transform/Base, each deed's last-fight amount), Kit, and Loadout (the tactic, `TacticPicker`) tabs. `PracticeSession` keeps `vows`, `transformed`, `snares`, and `last_deeds`. In a fight the small popup stays.
  A transformed hero stands as its path's figure, and paths are named under heroes while placing; a transformed Trapper's snares are markers dragged like heroes (`ArenaView.snare_dropped`). The result names paths and, for each hero on one, its deeds.
  The testing toggles (part 7, section 7: no combo readouts for players): "Target lines (for testing)" and "Combo readout (for testing)" (phase 5c step 9a: the heroes' engines under the chart, growing cards' counts at the end, and the damage rule's note on each number in the log), both off by default.
  `FightNames` turns ids into names ("Rift Hound 2"). `FightTally` (in `src/sim/`, shared with the sim runner) counts the chart. `FightBanners` shows a phase, the collapse, and the end.
- **Every kind of log entry needs a form on the board:** `test_every_encounter_plays.gd` has a table of them, and checks the board showed each kind a fight produced. A new log kind needs a row there as well as its audit rule in `test_arena_log.gd`.
- **Tests:** UI tests run headless and drive time by hand (`ArenaScreen._process(delta)`); `tests/ui/ui_test_kit.gd` finds and presses controls by text; `test_practice_flow.gd` drives a real `Main` from the title to the result. A test that replaces screens lets a frame pass before it ends, since `Main` frees the old screen on the next frame.

## The design the rebuild builds toward

These are summaries; the plans have the details and the decisions. As each phase lands, move its rules into a "how the code works" section here.

- **Heroes** (`rebuild-heroes.md`): a team of 3, chosen from Brannoc, Maren, Vell, Ilse (the Burn caster), Tamsin (the assassin), Garrow (the shield-bruiser), Aldous (the battery), Hob (the scavenger), Severine (the blood warlock), Edric (the team shielder), Ottilie (the alchemist), Lucan (the illusionist), and Kestra (the beastwarden), kept all run. Stats (HP, ATK, MGK, DEF, CRIT, ATSP, speed, range), a basic attack, a signature, a passive, sometimes a trait. Three paths each: vow at the start (a taste and a cost), transform when the path's deed fills, and later an apex (the vow opens after the Act 1 boss; each apex has a built-in snowball and 2 upgrades, `apexes.md`). Upgrade picks come after every won fight, not from deeds, from each hero's pool, their vowed path's taste upgrades, and once transformed its path upgrades (`upgrade-pools.md`; plain stat upgrades stack, locked in as a flat amount). Every deed must be hard to fill without its taste. Heroes have no ranks and no duplicates.
- **Between fights** (`rebuild-between-fights.md`, with the loadout pool in `loadout/`): each hero has loadout slots for tactics, gambits (one per hero), sigils, and charms (none are abilities; all are written against the slot, so they survive a transformation), bought with a currency and swapped freely. Every item has three ranks (each kind counts its own thing; a bought copy skips a rank). Any hero can hold any of them, with no warning when one does nothing; shops don't filter, any shop buys items back for half, and grafts are cut into charms; the Magpie is a rare node (`magpie.md`) that sells rank II charms and an epic or legendary relic, and is the only place to sell or swap a relic (the rest of the shops' setup is being redone). A hero who falls gets a wound (–15% max HP, up to 3); Rest clears them. The screens between fights and their item language (one frame shape per kind) are in the playtester's mock, `docs/mockups/hero-panel-layout.pdf` (part 6, section 9).
- **Signatures and mana:** a signature fires on a trigger: mana, HP threshold, a count, a set moment, or would-fall. Only signatures use mana; a unit without a mana signature has no mana bar. Silence stops mana gain. Stun doesn't, but a stunned unit can't fire a mana signature (other triggers still fire).
- **The arena** (`rebuild-arena.md`, `rebuild-phase1-arena-sim.md`): placement on flat-topped hexes (8 × 7, 3-row zones, a neutral middle row), then a fight on a free-moving plane. Units never overlap. Heroes come first in the fight's order. Targeting rules are data, with sticky targets. Melee lands when the attack finishes; ranged shots travel about 1 tick per hex and follow their target. Engage, Taunt, Stealth, knockback (a stopped push stuns), pulls, leaps, charges, flying, hop-away. Areas are warned and hit by center. Rift Collapse shrinks the arena one ring every 10s from 45s; crumbled ground is walkable and damages whoever stands on it (15 a second at first in Act 1, growing). Up to 30 standing units per side. A fight still running at 180s is a tie, and a tie counts as a guild victory.
- **Enemies** (`rebuild-enemies.md`): each tests one positioning question; hand-placed formations; elites built around one mechanic; Old Mother Ash with phases. Every elite and boss says what it does and what answers it. Harder means new problems, not more HP. Each enemy has 2 specializations (from day 5 of Act 1, in the harder fight), elites and the boss carry upgrades, Rift Tear adds rift modifiers, and the rift learns (a difficulty modifier) counters your habits (`enemy-growth.md`).
- **The run** (`rebuild-run.md`, with `days-and-nodes.md` and `events.md`): Act 1 is about 7 days; a day is a pick of 2 fights (known from the act's start), the loadout, placement, the fight, the after-fight pick and deed rewards, the shop (the Pedlar, every day: relics, loadout items, treating wounds), then 1 of 3 nodes (Camp always, and two of Event, Rift Tear with three depths, and the Magpie). Events carry the game's trade-offs, including the Bloodied Oath. A currency buys loadout things, relics, wound treatment, and rerolls; every source and price is in `economy.md` (start 10; a win 10, the harder fight 13, an elite 15, the boss 60; a wound 4). Relics have no downsides and come in five tiers (`relics/`: about 8–14 a run; every shop shows one, with climbing rerolls; legendaries in the shop after each boss; a boss relic after every boss). Duo bonds link two paths; once both heroes transform, the bond's free relic joins the shop pool (`docs/plans/duo-bonds.md`). A lost fight replays the day; the second loss ends the run; a tie pays like a win. The run is deterministic from its seed, like the sim, with separate streams for shops, picks, camp, and fights.
- **Combos** (`rebuild-combos.md`, part 7, agreed, not built): shared keywords (Marked, Rooted, Burning, Shielded, Stealthed), more triggers with a chain-depth guard, one damage rule (bonuses of the same kind add, different kinds multiply), upgrades and relics that grow all run (reset with the run, so rule 5 holds), every card's stat change with its amount, no combo readouts for players (only behind the testing toggle), and an endless mode after Act 3 (built after Act 1 until Acts 2 and 3 exist: phase 8 part 1) where the rift scales exponentially (`endless.md`: floors are days, ×1.15 a floor, stacking rift modifiers, a faster collapse, the deepest floor is the score).
- "Lowest HP" (heals and targeting) means lowest HP **percentage**.
- PvE only. Don't add networking or PvP code.

## How to work in this repo

- For any new system, propose a plan first (files, data shape, tests) and wait for approval before writing code. Each rebuild phase gets its own build plan before code is written.
- Write or update tests for sim logic in the same change. Determinism tests (run a seeded fight twice, compare logs) must keep passing once phase 1 brings them back.
- Keep changes small and focused. Don't refactor unrelated code.
- When adding content, validate the JSON with `tools/` before finishing, and run the balance sim on anything that changes numbers (once it's back).
- If a design question isn't answered in the design or the plans, ask instead of inventing an answer. Then note the answer in the matching plan's **Decisions**. Unanswered questions live under **Open questions** in `docs/design.md`.

## Tone and naming

The setting is the rift: dark and dangerous, with no warm hub to come home to. Content names should fit that. All art is placeholder until the art rehaul (rebuild phase 7). The game is asset-driven: new art follows `docs/plans/asset-contract.md`, and any asset not made for the game goes in `CREDITS.md` with its license. Don't use names, characters, or items from Guildrun, The Bazaar, or Enter the Gungeon.
